# SOL020 — Imports

## Description

`import module` loads `module.sole`; dotted paths select subdirectories. Access declarations and types through the full module name, or use `import module as alias` and access them through `alias`. For example, `import frontend.lexer as lexer` exposes `lexer.lex(...)`. Search checks the importing file's directory, the entry file's directory, then the standard library. Modules load once; cycles and namespace shadowing are errors. No wildcard imports or implicit re-exports.

An alias is a single identifier local to the importing module. It replaces the
original namespace rather than adding a second one. Aliases work for functions,
record types, constructors, methods, extern declarations, and core operations.
Different aliases for the same file share its declarations and type identity.
Duplicate bindings, reserved aliases, and rebinding an alias are errors.

Core operations follow the same rule: import `core` and call `core.len`,
`core.slice`, or `core.print`. Importing a module that uses `core` does not expose
it in the importing module. No functions are implicitly imported.

## Example

```sole
import core

import math as numbers

def main() -> void:
    core.print(numbers.gcd(48, 18))
```
